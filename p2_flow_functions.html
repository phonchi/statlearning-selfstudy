同一段程式碼貼三次，就是三個等著出錯的地方 課程 Lab Ch5 · 儲存格 24–26

假設你要比較三種多項式次數的驗證誤差。不寫函式的話，你會把同一段 「切分 → 配適 → 預測 → 算 MSE」複製三次，只改中間一個數字。 三份幾乎一樣的程式碼，就是三個各自會出錯、而且改了一份忘了改另外兩份的地方。

課程 lab 的做法 把那一段包成 evalMSE(terms, response, train, test)，然後用一個迴圈跑三次。程式碼從三十行變成六行，而且只有一個地方會錯。
包成一個函式
def evalMSE(terms, response, train, test): mm = MS(terms) X_train = mm.fit_transform(train) y_train = train[response] X_test = mm.transform(test) y_test = test[response] results = sm.OLS(y_train, X_train).fit() test_pred = results.predict(X_test) return np.mean((y_test - test_pred)**2)

這是課程 lab 真的在用的函式，不是教學範例。四個參數：要放哪些項、反應變數是誰、訓練集、測試集。

碰到 return，函式立刻結束並把值交出去，後面的行不會執行。沒有寫 return 的函式會回傳 None——忘記寫是很常見的 bug。

def evalMSE(terms, response, train, test): mm = MS(terms) X_train = mm.fit_transform(train) y_train = train[response] X_test = mm.transform(test) y_test = test[response] results = sm.OLS(y_train, X_train).fit() test_pred = results.predict(X_test) return np.mean((y_test - test_pred)**2)

四個參數、四個步驟、一個回傳值。注意它只用參數傳進來的東西，不去讀外面的全域變數。這叫「沒有副作用」，是好函式的特徵。

來源：Ch05-resample-lab-zh.ipynb · 儲存格 24
觀念釐清
參數（parameter）與引數（argument）差在哪？
定義函式時寫的名字叫參數（def evalMSE(terms, response, ...) 裡的 terms）；呼叫時實際傳進去的值叫引數。日常對話裡兩個字常常混用，看得懂就好。
為什麼不要在函式裡直接用外面的變數？
因為那樣它就不能重複使用了——換一份資料就得改函式本身。而且外面的變數被改掉時，函式的行為會跟著變，你卻看不出來。把需要的東西都當參數傳進去，函式才是一個可以信任的黑盒子。

PART 04 · 預設引數與作用域

函式裡看得到外面，外面看不到裡面 課程 Lab Ch5 · 儲存格 59–61

兩件事：預設引數讓常用的設定不必每次都寫， 作用域決定一個名字在哪裡看得到。 課程 lab 的 boot_SE 兩者都用上了。

有預設值的參數
def boot_SE(func, D, n=None, B=1000, seed=0): rng = np.random.default_rng(seed) first_, second_ = 0, 0 n = n or D.shape[0] for _ in trange(B): idx = rng.choice(D.index, n, replace=True) value = func(D, idx) first_ += value second_ += value**2 return np.sqrt(second_ / B - (first_ / B)**2)

n=None、B=1000、seed=0 都有預設值，所以呼叫時可以只給前兩個。有預設值的參數一定要放在沒有預設值的後面。

來源：Ch05-resample-lab-zh.ipynb · 儲存格 59
呼叫時只覆寫想改的
alpha_SE = boot_SE(alpha_func, Portfolio, B=1000, seed=0) alpha_SE

可變預設值的陷阱
def f(acc=[]) 這種寫法，那個空串列只會建立一次，後續每次呼叫都共用同一個，於是它會越積越多。要用可變的預設值，寫 def f(acc=None) 再在函式裡面 acc = acc or []。

traceback 要從最後一行開始讀 課程 Lab Ch2 · 儲存格 152

程式報錯不是壞事，是它在告訴你哪裡不對。真正該怕的是不報錯的錯。 Python 的錯誤訊息（traceback）要從最後一行開始讀： 最後一行是錯誤的種類與說明，往上是它發生在哪一行。

一個真的錯誤訊息
A[[1,3],[0,2,3]]
錯誤訊息
IndexError: shape mismatch: indexing arrays could not be broadcast together with shapes (2,) (3,)

最後一行說得很清楚：shape mismatch，兩個索引陣列的形狀 (2,) 與 (3,) 沒辦法一起廣播。看到 shape 就知道要去印 shape。這是 P3 的第一課。

最常見的四種錯
NameError 名字沒定義（多半是打錯字或儲存格沒跑）、KeyError 欄名不存在、IndexError 索引超出範圍、ValueError 型別對但值不合理（形狀對不上多半是這個）。
try / except 不是拿來蓋住錯誤的 try: ... except: pass 會把錯誤吞掉，讓程式帶著錯誤的狀態繼續跑——那正是你最不想要的「沉默的錯」。只有在你知道會發生什麼錯、而且知道該怎麼處理時才用它，例如「這個套件在 Colab 上才有，本機沒有就跳過」。
try: from google.colab import drive drive.mount('/content/drive') except ImportError: print('不在 Colab 上，跳過掛載')
錯誤多半的原因先去做什麼
NameError打錯字，或那個儲存格還沒跑從上到下重跑一次
KeyError欄名不存在或打錯印 df.columns
IndexError索引超出範圍印 len() 或 shape
ValueError: shape mismatch兩邊形狀對不上印兩邊的 shape
TypeError型別不對（例如字串當數字加）印 type() 或 dtypes
NotFittedError還沒 fit 就 predict檢查有沒有漏跑 fit

流程與函式速查表 先備 · 流程與函式

三張速查表。

情境用 and / or用 & / |
一個 if 判斷✓✗
選 DataFrame 的列✗（會報錯）✓
NumPy 陣列的條件✗✓
每個條件要不要括號不用一定要
「非」怎麼寫not x~mask
迴圈寫法什麼時候用
for x in a:只要值
for i, x in enumerate(a):同時要位置
for x, w in zip(a, ws):兩排東西並排走
for _ in range(B):只是要跑 B 次（自助法）
[f(x) for x in a]把結果收成一個串列
向量化（不寫迴圈）對整排數字做同一件事時的第一選擇
函式的部件怎麼寫注意
定義def name(a, b=預設):有預設值的參數放後面
回傳return 值沒寫就回傳 None
呼叫（位置）name(x, y)順序不能錯
呼叫（關鍵字）name(x, b=y)參數多時一律用這個
可變預設值def f(acc=None)不要寫 acc=[]
三個一定要記住的觀念 1. 選資料用 &／|，而且每個條件都包括號。and 一次只判斷一個真假值。
2. 同一段程式碼要寫第三次，就該包成函式。重複是沉默的錯的溫床。
3. traceback 從最後一行讀起。最後一行說錯在哪，往上找是誰呼叫的。
