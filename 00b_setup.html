PART 01 · Colab 工作流

開瀏覽器就有，但關掉就沒了 課程 Lab Ch1 · 儲存格 3–4

Colab 是跑在 Google 機器上的 Jupyter notebook。它的好處是零安裝、有免費 GPU； 代價是執行階段（runtime）會被回收——閒置太久或關掉分頁之後， 你裝的套件與記憶體裡的變數都會消失，程式碼本身則存在你的 Drive 裡不會掉。

最常見的一個誤會 「我明明裝過 ISLP 了，怎麼又說找不到？」，因為那是上一個執行階段裝的。重新連線之後要再跑一次 %pip install ISLP。把它留在 notebook 的第一格，就不會忘。

PART 02 · imports 那一格

每一份 lab 的第一格都長一樣，而且要先跑 課程 Lab Ch2 · 儲存格 3–8

每一份課程 lab 的第一格都長得差不多：把要用的套件全部 import 進來。 這一格一定要先跑，不然後面每一格都會報 NameError。

課程 lab 的 imports（第 2 章）
# 本 Notebook 使用的匯入（imports） import os # 檔案與環境變數/路徑處理 import numpy as np # 數值運算與陣列處理 import pandas as pd # 資料表格與資料處理 from matplotlib.pyplot import subplots # 建立子圖與繪圖版面 try: from google.colab import drive # Colab：掛載 Google Drive except Exception: drive = None # 非 Colab 環境

注意最後那段 try / except：google.colab 只有在 Colab 上才有，本機跑的時候讓它安靜地把 drive 設成 None 就好。這是 try/except 的正確用法。你知道會發生什麼錯、也知道怎麼處理。

環境的問題有八成是同樣的四種。這一節把它們列出來， 每一種都給「症狀 → 原因 → 怎麼修」。學會這四種，你以後遇到的環境問題會少一大半。

一個萬用的第一步
重啟 kernel 並從第一格全部重跑。這一步能解掉的問題比你想像的多，因為它同時消除了「亂序執行」與「殘留變數」這兩個最常見的干擾。
還是跑不動的話
問人之前先做這三件事
① 重啟並全部重跑；② 把完整的錯誤訊息最後一行複製起來；③ 確認是哪一格出錯、那一格用到哪些變數。做完這三件事，八成的問題你自己就解掉了；剩下的兩成，別人也才幫得上忙。
可以直接把錯誤訊息丟給 AI 嗎？
可以，而且通常很有用——環境問題正是 AI 最擅長的那一類（有標準答案、可驗證）。但要把完整的錯誤訊息與你實際跑的那一格都給它，不要只說「我的程式跑不動」。為什麼統計結果就不能這樣信它，見 00A。
交作業之前一定要做的一件事 重啟執行階段 → 從第一格全部重跑 → 確認每一格都有輸出而且沒有紅色錯誤。你不會想交出一份「只有我這台機器、而且只有照某個特定順序跑才對」的作業。
